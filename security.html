Protecting your account

Security at InkConnect

A clear view of the safeguards and limitations in the current application.

Last updated: November 4, 2026

Current application and deployment

This project currently defaults to a browser-based demo database when its backend URL is not configured. Demo data and sign-in state are kept in browser storage, so this mode is for testing and should not be used for real personal or payment information.

A live deployment can use the Google Apps Script backend and connected providers. Its security depends on the deployed configuration, access controls, provider settings, and hosting environment; this page does not certify a particular deployment.

Password and session safety

The current client code applies SHA-256 to a password before sending it to the API. SHA-256 is a fast general-purpose hash, not a password-storage algorithm; by itself, it does not provide the protections of a unique salt and a slow, adaptive password hash. Do not reuse a password from another service. Production use should replace this design with a vetted authentication system and a modern password-hashing approach.

Sign-in state is stored in browser local or session storage. Sign out on shared devices, keep your browser and device updated, and do not share passwords or verification codes.

Payments and third parties

Payment details may be processed by the payment provider you choose. Do not send card details, passwords, or other payment credentials in a message or support request. Review the provider's own security and privacy information before using its service.

Report a security concern

If you find a possible vulnerability or suspect an account has been compromised, please email support@inkconnect.com with a brief description. Do not include real user data, passwords, or payment information in your report. Please allow the team time to investigate before sharing details publicly.
